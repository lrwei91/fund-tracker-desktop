## 1. 业务背景与价值

### 1.1 业务背景

- 当前业务现状：个人投资者缺乏在本地常驻、离线优先、多源降级的轻量行情监控桌面工具；现有工程处于从 Electron 旧描述向 Tauri 2 目标架构收敛的落地阶段（X1 已裁决，权威）。
- 触发本次需求的事件：主理人冻结《高层架构设计》为单一事实来源（Tauri 2 + Rust），需将分散的资料与调研结论沉淀为用户可消费、研发可执行的用户故事与验收标准，驱动 MVP（F1–F12 + N1/N2）落地。
- 本系统在产品矩阵中的位置：在用户本机运行的「轻量、离线优先、多源降级」个人投资行情监控桌面应用，承担本地数据聚合与可视化层（见《高层架构设计》§4.2）。

### 1.2 行业方案

> 同类功能、痛点的行业标杆系统及解决方案（事实来自《research_report.md》§2/§3）：
> - Tauri 2：系统 WebView 渲染、Rust 核心、PCS 最小权限、包体约 600KB、不携带 Chromium/Node，已采纳为本项目外壳（加权评分 4.80，最高）。
> - Electron：内嵌 Chromium + Node，安装包 150–300MB，与「ZIP ≤ 20MB、不含 Chromium/Node」硬门禁直接冲突，否决。
> - Wails 3：系统 WebView + Go 后端，验证「系统 WebView + 极小包体」范式可行，但语言栈（Go）与已裁决 Rust 栈不符，仅部分借鉴范式。
> - TradingView 桌面端：实时多源行情 + 轻量桌面壳 + 跨设备同步的产品范式标杆，其「数据仅供参考」免责思路与本项目 D1 §6.5 一致。

### 1.3 方案收益与价值

| 项 | 说明 |
| --- | --- |
| 功能模块 | F1 大盘指数 / F2 自选分组 / F3 持仓成本备注 / F4 分时日K / F5 资金流 / F6 新闻公告 / F7 机会雷达 / F8 持仓浮窗 / F9 置顶提醒 / F10 提示音 / F11 托盘 / F12 多源降级 / N1 配置原子写入 / N2 包体门禁（F13/F14/F15 为完整版） |
| 预期价值收益 | 本地高频、实时、多源降级的个人投资行情监控；断流/降级时诚实表达不误导决策；轻量包体降低分发与运维成本 |
| 量化标准 | 普通请求并发 ≤ 3；东方财富单并发 + 启动间隔 1–1.3s；403/连续失败 5 分钟熔断 + 半开仅放行一次探测；数据源不可用诚实表达覆盖率 100%；分发 ZIP ≤ 20MB（Windows/macOS 均满足）；浅色/深色一致性 100% |

### 5.2 EPIC-A：散户投资者 · 行情与资讯监控

#### 5.2.1 US-1 大盘指数监控（F1，MVP）

##### 5.2.1.1 业务场景
- 角色：散户投资者
- As a（作为）散户投资者，I want（我希望）打开应用即可看到主要指数列表及每只指数的迷你分时走势，so that（以便）快速判断大盘冷暖而不必逐一打开个股。
- 描述逻辑：用户启动应用后默认进入大盘/自选页，指数列表与迷你图在实时刷新下保持可读。

##### 5.2.1.2 业务流程
- 主窗口加载 → 刷新协调器发起合并行情请求 → Rust gateway 经腾讯主源取指数 → 渲染指数列表与真实 242 点分时迷你图 → 迷你图按可见区域懒加载且并发 ≤ 2。

##### 5.2.1.3 UE 原型
- 大盘/自选页：顶部指数横向列表，每只指数含名称、最新价、涨跌幅、242 点分时迷你图；悬停迷你图展示分时关键信息。

##### 5.2.1.4 业务逻辑
- 指数迷你图必须使用真实 242 点分时数据，不生成模拟曲线；主源腾讯无独立备用源，主源不可用时该指数以 available:false 表达，列表其余项不受影响。

##### 5.2.1.5 数据描述
- 数据经 Rust gateway（合并在途 + TTL 缓存）返回；每条指数含 code/name/price/changePct/series(242 点)/available 元数据。

##### 5.2.1.6 验收标准 AC
- Given（给定）用户已启动应用并进入大盘标签页 When（当）指数列表完成首屏加载 Then（那么）每只指数展示真实 242 点分时迷你图，且系统不渲染任何模拟曲线，核心路径 ≤ 3 步（启动→进入大盘→看到指数）。
- Given（给定）腾讯主源对某指数返回空值或不可用 When（当）页面刷新该指数 Then（那么）该指数项以 available:false 诚实表达，不伪装为零值或确定涨跌，且其余指数保持正常显示。
- Given（给定）用户处于浅色/深色任一主题 When（当）大盘页渲染 Then（那么）指数列表与迷你图遵循统一白纸黑墨荧光黄体系，红涨绿跌语义保持一致。
- Given（给定）窗口宽度缩至 540px When（当）大盘页布局重排 Then（那么）指数列表与迷你图在断点内可读，不出现横向溢出。

##### 5.2.1.7 外部集成接口
- 腾讯行情源（实时行情/指数），经 Rust gateway 接入；可用性待裁决（U-01）。

#### 5.2.2 US-2 自选股分组管理（F2，MVP）

##### 5.2.2.1 业务场景
- 角色：散户投资者
- As a 散户投资者，I want 对自选股进行分组、增删改与排序，so that 按关注维度组织标的、缩短查找路径。
- 描述逻辑：用户在自选页管理分组，操作即时持久化到 config.json v2。

##### 5.2.2.2 业务流程
- 进入自选页 → 新建/重命名/删除分组 → 调整分组顺序 → 配置写入 config.json v2（原子写入）→ 反馈回路重新调度刷新。

##### 5.2.2.3 UE 原型
- 自选页：左侧分组导航（可拖拽排序）、右侧分组内标的列表；分组切换为单步操作。

##### 5.2.2.4 业务逻辑
- 分组元数据经 config.json v2 原子写入 + 旧字段兼容；排序与增删改在本地完成，不触外部网络。

##### 5.2.2.5 数据描述
- config.json v2 内 groups 结构：id/name/order/items[]；写入为原子替换，失败回滚旧文件。

##### 5.2.2.6 验收标准 AC
- Given（给定）用户进入自选页并点击新建分组 When（当）用户输入分组名并确认 Then（那么）新分组出现在导航中，核心路径 ≤ 3 步（进入→新建→命名确认），且配置以原子写入落盘不损坏旧数据。

### 5.5 EPIC-D：合规运维 · 数据可靠性与分发合规

#### 5.5.1 US-15 多源降级与熔断（F12，MVP）

##### 5.5.1.1 业务场景

##### 5.5.1.2 业务流程

##### 5.5.1.4 业务逻辑

##### 5.5.1.5 数据描述

##### 5.5.1.6 验收标准 AC

- Given（给定）某源连续返回网络/429/5xx 失败 When（当）达到熔断阈值 Then（那么）触发 5 分钟熔断并切换备用源，标注实际来源。

##### 5.5.1.7 外部集成接口

## 6. 非功能性需求

### 6.1 易用性需求

- 核心路径 ≤ 3 步：启动→进入大盘、进入详情→切 Tab、配置→触发→看到提醒等主链路均 ≤ 3 步。
- 状态表达规范（D3 §5）：loading 保留最终布局刷新不清空旧内容；empty 解释当前结果；error 提供可恢复操作。
- 浅色/深色模式统一（light/dark）：白纸/近黑文字/32px 细网格/单一荧光黄；深色中性碳黑灰阶不回退旧冷蓝；success/warning/error/info 与涨跌色独立，状态同时用文字 + 结构表达。
- 操作一致性：分组管理、持仓编辑、提醒配置均提供即时反馈与可恢复入口。
- 低打扰：浮窗/置顶提醒/提示音不打断主工作流，支持免打扰。

### 6.2 性能响应需求

- 普通请求并发上限 ≤ 3；东方财富单并发 + 启动间隔 1–1.3s。
- 实时行情优先、同周期仅一个合并行情请求；页面隐藏暂停后台刷新。
- 迷你图按可见区域懒加载并限 2 并发；指数迷你图真实 242 点分时。
- 熔断：403 立即熔断；连续网络/429/5xx 失败熔断 5 分钟，半开仅放行一次探测。
- TTL 缓存 + 合并在途请求降低上游压力；本地缓存可重拉。

### 6.3 操作与环境需求

- 目标架构：Tauri 2 + Rust（X1 已裁决）；原生 HTML/CSS/JavaScript 前端；Rust 进程内 gateway。
- 响应式断点：最小窗口 540px；592px 单列 + 底部导航；760px 双列；1280px 侧栏 + 三列工作台；320/390px 仅验证 WebView 内容回退。
- Windows 依赖系统 WebView2（不携带离线运行时）；macOS 用系统 WKWebView，未公证（MVP 走 xattr 文档）。
- 包体门禁：分发 ZIP ≤ 20MB，不含 Chromium/Node/Python/TDX。
- 权限最小化：仅开放事件能力，不开放任意文件系统/shell/进程访问。
- 验收覆盖：主窗口三页/设置/自选数据/个股详情/持仓浮窗/告警弹窗，及浅色/深色/键盘/减弱动效/200% 缩放/失败状态。

### 6.4 安全性需求

#### 6.4.1 安全密码设置
- 本工具无账号密码体系；不适用账号密码强度要求。本地无远程账户，不涉及登录凭证。

#### 6.4.2 安全软件架构
- 应用仅开放事件能力（Tauri commands/events），不开放任意文件系统/shell/进程访问（D1 §6）。
- 前端与 Rust 核心经 IPC 桥接，WebView 代码仅能访问被暴露的资源（PCS 权限/能力/作用域）。

#### 6.4.3 安全设计
- 本地配置经 config.json v2 原子写入，防损坏；敏感字段（持仓成本/备注）加密策略待裁决（U-02，由安全设计定稿）。
- 自动更新（完整版）强制签名验证 + 端点强制 HTTPS，验证不可禁用（U-03）。

#### 6.4.4 安全开发
- 数据可靠性口径作为开发约束：空值以 null/available:false 诚实表达，不伪装为零值/红绿/净流入。
- 外部链接（公告 PDF 等）仅通过受限外部链接打开，不在应用内渲染未授权内容。
- 多源 handler 保留来源/降级/不可用元数据，下游按元数据诚实表达，避免误导结论。

#### 6.4.5 安全测试和部署
- 构建期校验包体门禁（≤ 20MB）与运行时携带清单（不含 Chromium/Node/Python/TDX）。
- 自动更新端点安全（完整版）随安全设计落地；MVP 分发经文档化步骤降低风险。

#### 6.4.6 数据安全
- 用户数据写入产品名目录 config.json v2（macOS ~/Library/Application Support/恭喜发财；Windows %APPDATA%\恭喜发财）。
- 敏感字段加密与密钥管理待裁决（U-02）；Web 缓存可重拉，不长期缓存快讯超时正文（U-04）。
